# Current ComplyWise product scenario — 2026-10-04

This describes the inspected implementation, not a proposed architecture. Real-provider evidence and browser fixtures are reported separately. The submission is not certified legally accurate by these engineering tests.

1. **Authentication:** Next.js/React frontend; Django/DRF token login/register/logout. Google code flow with PKCE and single-use handoff already exists. Google Auth client credentials remain external setup; Calendar credentials are separate. Password credentials remain manual; no one-click credential login. Duplicate registration says “The user already exists. Please sign in.”
2. **Starting profiles:** Seven editable starting profiles: Restaurant, Manufacturing, Retail, IT, Warehouse, Healthcare, Renewable Energy. Own-business clears inherited facts; choosing a profile neither submits nor answers questions.
3. **Onboarding:** Visible selector, canonical business facts, description, business understanding, zero to five questions, analysis, results. Add-business uses /onboarding?new=true. Resume passes explicit IDs and suppresses repeated development initialization.
4. **Business profile:** Immutable revisions; unknown variable keys rejected. Financial unknowns stay unknown. Revised MSME classification is a coarse aid; not registration or entitlement. Historical as_of classification remains available.
5. **Assessment lifecycle:** Orchestration adopts an active onboarding assessment under a business lock. UI checkpoints merge without erasing server stage state. Assessment/profile/tenant scoping is preserved.
6. **Adaptive questions:** Existing LLM planner and published-rule AST gaps use the requested assessment snapshot, description, previous answers and canonical aliases. Identity dedup preserves known False/zero and suppresses answered facts even with another key/wording. At most five ranked unresolved questions; other gaps persist. Metadata distinguishes rule-fact from contextual source-discovery basis. Starter suggestions are editable and require confirmation, not silent verification. Numeric types render inputs; connected load uses HP. Question policy version4 invalidates old presentation metadata. Real five-business counts2/3/1/2/3 with zero repeated known facts; no positive live starter suggestion was needed in those runs.
7. **SERP API:** SerpApi, Google /search.json, organic_results. SERPAPI_API_KEY or SERP_API alias. Backend-only; twenty-second timeout; no transport retry storm; authentication/rate cooldown; snippets cannot become captures. Independent planned searches use up to three workers.
8. **Crawlee:** Python1.7.2 HttpCrawler with HTTPX, PlaywrightCrawler with real Chromium. Thin HTML routes once to browser within remaining budget; blocked/login/CAPTCHA/destination failures do not. Official domains, public DNS destinations, redirects, MIME, size, text and soft-homepage redirects are checked. Capture records normalized/raw hashes, mode and metadata. Dates are retained only when supplied. Raw bytes are hashed, not durably archived by this adapter.
9. **RAG:** Existing deployed ComplianceRAG /retrieval/search returns actual chunk/source context. Adapter filters source/jurisdiction; infrastructure/empty results do not consume LLM fallback. Local retrieval uses verified evidence token overlap. pgvector presence is not proof of a wired local vector/chunk/reranker stack; external service internals were not audited.
10. **Gemini rotation:** Current Gemini primary and three distinct configured slots. Healthy requests start1,2,3,1; rotated attempt chain tries each eligible slot once. Known unavailable slots cool down. Cursor/cooldown are process-local; project/quota independence is unknown.
11. **OpenAI fallback:** Last available fallback for Gemini-primary requests. Reverse recursion disabled. Logical request IDs keep attempts in one call budget; token/cost limits remain. Attempt telemetry distinguishes provider/slot/model/latency/failure; monetary estimates are not audited vendor pricing.
12. **Contextual fallback:** Separate persisted WorkspaceGuidance. Validation prohibits invented URLs/IDs/verification and unsupported specific procedural details. Planning suggestions retain LLM_FALLBACK_RESULT/SUGGESTED; they cannot publish a legal rule. Schemes/standards retain contextual identity. Prompts/schemas do not prove semantic accuracy.
13. **Deterministic applicability:** Existing published rules, AST, verified evidence, jurisdiction and precedence engine retained. New captures and extracted claims are quarantined until authorized review. Discovery alone cannot create statutory APPLICABLE decisions.
14. **Compliance:** Saved engine decisions take precedence; contextual suggestions coexist without fabricated rule references. Links retain assessment scope. Explanation modal uses actual excerpts/facts, without invented traces, description-as-quote or verified-authority footer. Completed onboarding reads canonical persisted results; no made-up counts or certainty claims. Unreviewed items remain unconfirmed.
15. **Documents:** Source-backed checklists where available and ordinary preparation guidance. Contextual checklists say Planning basis, other records Requirement basis; requirement links retain assessment_id. No invented authority fallback. Uploads persist version identity; checks are preliminary; missing OCR is a recorded failure/review state, not success. Live external object storage was not verified by document-list or fixture-upload tests.
16. **Workflows:** Existing prerequisite/step/case system and persisted progress; guidance uses practical steps without guessed statutory fees/deadlines.
17. **Schemes:** Existing persisted matcher plus contextual support areas. Warm business-context panel retained; removed hardcoded catalogue count. Empty matches remain honest.
18. **Standards:** Applicable published decisions with verified evidence form reviewed matches. Explicit business/assessment URLs cannot inherit a foreign active assessment. Contextual planning exposes relevance/source reference; missing URLs remain absent and mandatory status unknown. Service errors are not empty success. 20. **Admin:** Superuser-only atomic owner/business creation and same starter selector; manual optional new-user credentials; no role grants/token return. Reviewers retain assignment/publication boundaries and can enter normal assessment onboarding. Review/publication propagation tests remain.

22. **Performance:** Cached understanding/plans/workspace, empty-section cache, assessment reuse, no duplicate question initialization, no repeated empty decision run. Searches parallel; captures currently bounded and serial. No zero-latency claim.

Unused Firecrawl credential may remain in local .env, but runtime settings/discovery do not read or call it; inert legacy module cannot make network requests.
